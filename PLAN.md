# План розвитку Victory Index

Два наступні таски. Кожен розписаний так, щоб свіжа сесія Claude без контексту
попередніх розмов могла виконати його від початку до кінця. Виконувати по черзі:
спочатку Таск 1, потім Таск 2 (Таск 1 змінює процедуру скіла, яку Таск 2 доповнить
ще раз).

**Передумова для обох тасків.** Наразі вся робота живе в гілці
`claude/ukraine-russia-balance-index-7mk3zr`, і дефолтної гілки `main` в репозиторії
немає. Перед виконанням тасків злий цю гілку в `main` (створи `main` від неї і зроби
дефолтною, або змерж через PR) — щотижневі автозапуски і свіжі сесії мають працювати
від дефолтної гілки. Якщо на момент виконання `main` уже існує і містить скіл —
передумова виконана, пропусти.

## Таск 1: Автоматичний щотижневий запуск — ✅ ВИКОНАНО (2026-08-23)

Гілка `main` створена і зроблена дефолтною. Routine
`trig_0165QziaXSVjMBnkAw1iRK6t` («Victory Index — щотижневий розрахунок»)
працює: **неділя 06:00 UTC**, свіжа сесія на кожен запуск, сповіщення на пошту,
пуш прямо в `main`. Тестовий прогін через `fire_trigger` пройшов увесь цикл і
запушив коміт `a78dc76`. Керування описано в README, розділ «Автоматизація».

Дві граблі, на які натрапили (враховано в промпті тригера):
- свіжа сесія не має репозиторію в authorized set → перший крок промпта —
  `add_repo` з `access: "push"` і `register_repo_root`;
- у налаштуваннях Routine лишається outcome-гілка `claude/...` — промпт явно
  вказує працювати і пушити в `main`.


**Мета.** Щосуботи скіл `victory-index` запускається сам: збирає дані, рахує
індекси, комітить звіт у `journal/` та оновлення `data/history.json` у `main`.
Без ручної участі.

### Кроки

1. **Перевір ручний запуск від main.** У сесії на гілці `main` запусти
   `/victory-index`. Переконайся, що скіл: прочитав `data/history.json`, зібрав
   свіжі дані, порахував дельти відносно попереднього запуску (перший запуск від
   2026-08-23 уже в історії — дельти мають з'явитись), записав звіт, оновив
   історію, закомітив і запушив. Якщо щось у процедурі скіла незрозуміло чи
   зламано — спочатку полагодь `.claude/skills/victory-index/SKILL.md`.

2. **Створи щотижневий Routine (тригер).** Використай інструмент
   `create_trigger` MCP-сервера Claude Code Remote з такими параметрами:
   - `name`: `Victory Index — щотижневий розрахунок`
   - `cron_expression`: `0 6 * * 6` (субота 06:00 UTC = 09:00 Києва влітку,
     08:00 взимку; час можна змінити на смак)
   - `create_new_session_on_fire`: `true` — кожен запуск у свіжій сесії
   - `initiation`: `human_request`
   - `notifications`: `{"push": true}` — пуш на телефон, коли звіт готовий
   - `prompt` (самодостатній, бо сесія стартує з нуля):
     > У репозиторії atmadev/ukraine-victory-index (гілка main) виконай скіл
     > /victory-index: зроби повний щотижневий розрахунок — прочитай попередній
     > стан з data/history.json, збери свіжі дані за каталогом джерел, оціни
     > фактори відносно попереднього запуску, порахуй обидва індекси, запиши
     > звіт у journal/YYYY-MM-DD.md, додай запис у data/history.json, закоміть
     > з повідомленням "index: звіт за YYYY-MM-DD (БС X, СТ Y)" і запуш у main.
     > Якщо існує data/artifact.json — онови також дашборд-артефакт за
     > інструкцією зі SKILL.md.

3. **Перевір тригер.** Виклич `fire_trigger` для щойно створеного тригера
   (позаплановий запуск) і переконайся, що свіжа сесія відпрацювала весь цикл
   і новий звіт з'явився в `main`. Якщо сесія спіткнулась (не знайшла репозиторій,
   не змогла запушити) — поправ prompt тригера через `update_trigger` і повтори.

4. **Задокументуй.** Додай у README розділ «Автоматизація»: розклад, як подивитись
   тригери (`list_triggers`), як поставити на паузу (`update_trigger` з
   `enabled: false`), як запустити позапланово (`fire_trigger`).

### Критерії готовності
- [x] Тригер існує, увімкнений, розклад щотижневий.
- [x] Тестовий запуск через `fire_trigger` створив повноцінний звіт у `main`.
      Дельти на тестовому прогоні нульові — він відбувся того самого дня, що й
      базовий запис; перші справжні тижневі дельти буде видно 30.08.
- [x] README пояснює, як керувати автоматизацією.

## Таск 2: HTML-дашборд (артефакт)

**Мета.** Красива самодостатня HTML-сторінка (артефакт Claude), що показує
поточні значення обох індексів, розбивку по під-індексах і графіки динаміки
з `data/history.json`. Оновлюється при кожному тижневому запуску скіла,
зберігаючи той самий URL.

### Вимоги до сторінки

**Джерело даних.** Єдине джерело правди — `data/history.json` (плюс 2–3 ключові
події з останнього звіту в `journal/`). Дані вбудовуються в HTML при генерації
(сторінка статична, без зовнішніх запитів — CSP артефактів однаково їх заблокує).

**Зміст сторінки, згори вниз:**
1. Заголовок + дата останнього розрахунку + дисклеймер (аматорський проєкт,
   цінність у динаміці, не військова аналітика).
2. Два «герої»-показники поруч:
   - **Баланс сил**: значення на шкалі −100…+100 з візуалізацією типу
     диверджентного індикатора з нулем-паритетом посередині; підпис семантики
     (плюс = перевага України); дельта за тиждень зі стрілкою.
   - **Стратегічний індекс**: значення на шкалі 0…100 (прогрес-бар до «стійкого
     вигідного миру»); дельта за тиждень.
   - Шкали різні — НЕ уніфікувати і не усереднювати; кожен показник підписаний
     власною семантикою.
3. Розбивка балансу сил: 4 під-індекси (військовий, економічний, людський,
   міжнародний) диверджентними барами −100…+100 з вагами.
4. Розбивка стратегічного: 3 компоненти (гарантії безпеки, ЄС та відбудова,
   справедливість) прогрес-барами 0–100 з вагами.
5. Два окремі графіки динаміки (лінійні, по осі X — дати запусків):
   - Баланс сил + його 4 під-індекси (вісь −100…+100, нульова лінія виділена).
   - Стратегічний + його 3 компоненти (вісь 0…100).
   Поки в історії мало точок — графіки все одно мають коректно рендеритись
   (1–2 точки: показувати маркери, не ламатись).
6. Ключові події останнього тижня (3–5 пунктів з останнього звіту).
7. Футер: посилання-згадка методології (версія), дата генерації.

**Технічні вимоги:**
- Перед версткою ОБОВ'ЯЗКОВО завантаж скіли `artifact-design` і `dataviz`
  (інструментом Skill) — палітра, правила діаграм і тем звідти.
- Мова — українська. Тема — світла й темна (theme-aware за правилами артефактів).
- Графіки — inline SVG без зовнішніх бібліотек.
- `<title>` — коротка назва (напр. «Victory Index»), favicon-емодзі стабільний
  (напр. 📊), опис одним реченням.

### Кроки

1. Завантаж скіли `artifact-design` і `dataviz`.
2. Напиши генератор `scripts/build_dashboard.py`: читає `data/history.json`
   (і останній файл з `journal/` для блоку подій), генерує `dashboard/index.html`
   за вимогами вище. Генератор — щоб тижневі запуски не верстали сторінку з нуля,
   а лише перезапускали скрипт на свіжих даних. Без зовнішніх залежностей
   (тільки stdlib Python).
3. Запусти генератор, опублікуй `dashboard/index.html` інструментом Artifact.
4. Збережи URL опублікованого артефакту в `data/artifact.json`:
   `{"dashboard_url": "https://claude.ai/…"}` — щоб наступні сесії оновлювали
   той самий артефакт (параметр `url` в Artifact), а не плодили нові.
5. Додай у `.claude/skills/victory-index/SKILL.md` крок 8 процедури:
   після оновлення історії запустити `python3 scripts/build_dashboard.py`,
   опублікувати `dashboard/index.html` через Artifact з `url` із
   `data/artifact.json`, і лише потім комітити (щоб згенерований HTML теж
   потрапив у коміт).
6. Онови README: додай посилання на дашборд і опис структури
   (`scripts/`, `dashboard/`, `data/artifact.json`).
7. Закоміть і запуш.

### Критерії готовності
- [ ] `scripts/build_dashboard.py` детерміновано збирає сторінку з
      `data/history.json`; падає з зрозумілою помилкою, якщо історія порожня.
- [ ] Артефакт опубліковано, URL збережено в `data/artifact.json`.
- [ ] Сторінка коректна в світлій і темній темі, без горизонтального скролу,
      графіки не ламаються на 1–2 точках історії.
- [ ] SKILL.md містить крок оновлення дашборда; README оновлено.

### Готовий промпт для свіжої сесії

```
Прочитай PLAN.md у репозиторії ukraine-victory-index і виконай Таск 2
(HTML-дашборд): згенеруй сторінку з data/history.json, опублікуй як артефакт,
збережи URL у data/artifact.json і вбудуй оновлення дашборда в процедуру скіла
victory-index.
```

## Після виконання обох тасків

Повний цикл виглядає так: щосуботи тригер будить свіжу сесію → скіл збирає дані
й рахує індекси → звіт у `journal/`, запис у `data/history.json` → генератор
перезбирає `dashboard/index.html` → артефакт оновлюється за тим самим URL →
коміт у `main` → пуш-сповіщення на телефон. Ручна участь — лише переглядати
звіти й іноді підкручувати методологію (з бампом версії в
`references/methodology.md`).
